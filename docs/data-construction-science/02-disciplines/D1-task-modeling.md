# D1. 任务建模科学（Task Modeling Science）

## 定义

**任务建模科学**研究如何将业务需求系统化地转化为可执行的数据构建任务，包括任务形式化、标签空间设计、输入输出模式定义、指标体系构建等。

> **核心问题**：如何把"我想做一个XXX系统"变成"我需要构建什么样的数据集"？

## 为什么需要任务建模？

### 问题场景

❌ **错误示例**：
```
产品经理：我们要做一个智能客服系统
工程师：好的，我去收集对话数据
（3个月后）
产品经理：这个模型怎么表现这么差？
工程师：数据不是都标注了吗？
```

问题根源：**任务定义不清晰**

✅ **正确示例**：
```
1. 任务形式化：多轮对话 → 意图识别 + 槽位填充 + 回复生成
2. 标签空间：50个意图类别 + 20个槽位类型
3. 输入模式：用户query + 上下文（最近3轮）
4. 输出模式：结构化槽位 + 文本回复
5. 评估指标：意图准确率、槽位F1、回复BLEU、用户满意度
```

## 核心内容

### 1. 任务形式化（Task Formalization）

将自然语言描述转化为数学形式。

#### 典型任务类型

| 任务类型 | 形式化定义 | 输入 | 输出 | 典型应用 |
|---------|-----------|------|------|---------|
| **分类** | f: X → Y, Y={c1,c2,...,cn} | 文本/图像 | 类别 | 情感分类、图像识别 |
| **序列标注** | f: X → Y^n, Y={tag1,...,tagm} | 序列 | 标签序列 | NER、词性标注 |
| **生成** | f: X → Y, Y=自由文本 | 文本 | 文本 | 翻译、摘要 |
| **问答** | f: (Q, C) → A | 问题+上下文 | 答案 | 阅读理解、QA |
| **检测** | f: I → {(bbox, class)}* | 图像 | 框+类别 | 目标检测 |
| **排序** | f: (q, {d1,...,dn}) → rank | 查询+文档集 | 排序 | 搜索、推荐 |
| **对话** | f: (U, H) → R | 用户输入+历史 | 回复 | 客服、助手 |

#### 任务分解示例：OCR系统

```
业务需求：识别身份证信息

任务分解：
├── 子任务1：文本检测（Detection）
│   ├── 输入：身份证图像
│   ├── 输出：文本区域边界框
│   └── 标签：{文本/非文本} + bbox
│
├── 子任务2：文本识别（Recognition）
│   ├── 输入：裁剪的文本区域
│   ├── 输出：文字序列
│   └── 标签：字符序列
│
└── 子任务3：信息提取（Information Extraction）
    ├── 输入：识别文本
    ├── 输出：结构化信息
    └── 标签：{姓名, 身份证号, 地址, ...}
```

### 2. 标签空间设计（Label Space Design）

定义"什么是正确答案"。

#### 设计原则

1. **互斥性（Mutual Exclusivity）**
   - 每个样本只能属于一个类别（多分类）
   - 或明确允许多标签（多标签分类）

2. **完备性（Completeness）**
   - 覆盖所有可能的情况
   - 包含"其他"类别作为兜底

3. **可区分性（Distinguishability）**
   - 类别间有明确边界
   - 标注者能够一致地判断

4. **粒度适当（Appropriate Granularity）**
   - 不要过细（导致样本不足）
   - 不要过粗（导致混淆）

#### 标签空间设计案例

**案例1：情感分类**

❌ **不良设计**：
```
标签：{正面, 负面}
问题：中性评论无法处理
```

✅ **改进设计**：
```
标签：{正面, 负面, 中性}
或层次化：
├── 极度正面
├── 正面
├── 中性
├── 负面
└── 极度负面
```

**案例2：医疗图像诊断**

❌ **不良设计**：
```
标签：{正常, 异常}
问题：异常类型多样，模糊不可用
```

✅ **改进设计**：
```
层次化标签：
├── 正常
└── 异常
    ├── 肿瘤
    │   ├── 良性
    │   └── 恶性
    ├── 炎症
    └── 其他病变
```

### 3. 输入输出模式设计（I/O Schema Design）

定义数据的结构形式。

#### 输入模式设计

| 模态 | 原始形式 | 结构化形式 | 预处理 |
|------|---------|-----------|--------|
| **文本** | 字符串 | Token序列 | 分词、编码 |
| **图像** | 像素矩阵 | Tensor(H,W,C) | 归一化、裁剪 |
| **语音** | 波形 | 频谱特征 | MFCC、Mel |
| **表格** | CSV/SQL | DataFrame | 特征工程 |
| **多模态** | (图,文)对 | 对齐表示 | 跨模态对齐 |

#### 输出模式设计

**示例：命名实体识别**

方案1：BIO标注
```json
{
  "text": "Apple公司位于加州",
  "labels": ["B-ORG", "I-ORG", "O", "O", "O", "B-LOC", "I-LOC"]
}
```

方案2：Span标注
```json
{
  "text": "Apple公司位于加州",
  "entities": [
    {"start": 0, "end": 2, "type": "ORG", "text": "Apple公司"},
    {"start": 5, "end": 7, "type": "LOC", "text": "加州"}
  ]
}
```

**选择依据**：
- BIO：适合序列模型（LSTM、CRF）
- Span：适合Transformer模型，更直观

### 4. 指标体系构建（Metrics Science）

量化"什么叫模型好"。

#### 指标分层

```
指标体系
├── 基础指标（Model-centric）
│   ├── 分类：Accuracy, Precision, Recall, F1
│   ├── 生成：BLEU, ROUGE, Perplexity
│   ├── 检测：mAP, IoU
│   └── 排序：NDCG, MRR
│
├── 业务指标（Business-centric）
│   ├── 转化率、留存率
│   ├── 用户满意度（CSAT）
│   └── ROI、成本节省
│
└── 质量指标（Quality-centric）
    ├── 鲁棒性（对抗样本准确率）
    ├── 公平性（跨群体性能差异）
    ├── 延迟（Latency）
    └── 可解释性（Explainability）
```

#### 指标设计原则

1. **可度量性**：能够自动计算
2. **可解释性**：能够向业务方解释
3. **可优化性**：能够作为训练目标
4. **全面性**：覆盖多个维度

#### 指标选择案例

**任务：推荐系统**

❌ **单一指标**：
```
只看点击率（CTR）
→ 可能推荐clickbait内容，长期伤害用户体验
```

✅ **多维指标**：
```
1. 相关性：CTR, 观看时长
2. 多样性：类别覆盖度
3. 新鲜度：新内容占比
4. 公平性：小众内容曝光率
5. 业务：DAU增长、收入
```

### 5. 数据需求度量（Data Requirement Modeling）

估算"需要多少数据"。

#### 数据规模估算公式

**经验公式**：
```
N_samples ≈ K × N_params / (Log2(N_classes) + 1)
```

其中：
- N_params：模型参数量
- N_classes：类别数
- K：经验系数（通常5-10）

**更精确的方法**：学习曲线外推
1. 用小数据集训练
2. 绘制数据规模 vs 性能曲线
3. 拟合幂律函数：`Acc = a - b * N^(-c)`
4. 外推目标规模

#### 不同任务的数据需求

| 任务类型 | 最小规模 | 理想规模 | 说明 |
|---------|---------|---------|------|
| **简单分类** | 100/类 | 1000/类 | 类别少、特征明显 |
| **复杂分类** | 500/类 | 5000/类 | 类别多、边界模糊 |
| **NER** | 1000句 | 10000句 | 需覆盖实体多样性 |
| **对话** | 5000轮 | 50000轮 | 需覆盖场景多样性 |
| **OCR** | 10000字 | 100000字 | 需覆盖字体、场景 |
| **医疗图像** | 500/类 | 5000/类 | 专家标注成本高 |
| **大模型微调** | 1000样本 | 10000样本 | 依赖预训练 |

## 实践方法论

### 步骤1：需求澄清

**问题清单**：
- [ ] 业务目标是什么？（提升什么指标？）
- [ ] 输入是什么？（文本/图像/语音/...）
- [ ] 期望输出是什么？（分类/生成/...）
- [ ] 性能要求是什么？（准确率>90%？延迟<100ms？）
- [ ] 约束条件是什么？（成本、合规、...）

### 步骤2：任务分解

使用思维导图或流程图分解任务：
```
主任务
├── 子任务1
│   ├── 数据需求
│   └── 评估指标
└── 子任务2
    ├── 数据需求
    └── 评估指标
```

### 步骤3：标签体系设计

1. 列举所有可能的输出
2. 分组和层次化
3. 定义边界case处理规则
4. 编写标注协议草案

### 步骤4：指标定义

1. 定义核心指标（北极星指标）
2. 添加辅助指标（质量、公平性等）
3. 设定baseline和目标值
4. 确定评估数据集划分

### 步骤5：数据规模规划

1. 估算初始规模（最小可行数据集）
2. 规划迭代路径（v1 → v2 → v3）
3. 评估资源需求（人力、时间、成本）

## 常见陷阱

### 陷阱1：任务定义过于模糊

❌ "做一个智能问答系统"
✅ "基于公司FAQ构建检索式问答，准确率>85%，支持1000个常见问题"

### 陷阱2：标签过于复杂

❌ 100个细粒度情感类别
✅ 先做5个粗粒度类别，再根据需要细化

### 陷阱3：指标与目标不一致

❌ 优化BLEU，但用户关心可读性
✅ 同时优化BLEU和人工评估满意度

### 陷阱4：数据需求估算过于乐观

❌ "我们100个样本训个模型试试"
✅ "根据学习曲线，至少需要1000样本才能达到baseline"

## 案例：文本分类任务建模

### 场景
构建新闻分类系统，将新闻自动归类到不同频道。

### 建模过程

1. **任务形式化**
   - 类型：多分类
   - 输入：新闻标题 + 正文（前500字）
   - 输出：类别（单标签）
   - 形式化：`f: Text → Category`

2. **标签空间**
   ```
   10个一级类别：
   - 科技、财经、体育、娱乐、社会、
     军事、教育、健康、旅游、其他
   ```

3. **数据模式**
   ```json
   {
     "id": "news_001",
     "title": "...",
     "content": "...",
     "category": "科技",
     "timestamp": "2025-12-11"
   }
   ```

4. **评估指标**
   - 核心：Accuracy, Macro-F1
   - 辅助：每个类别的Precision/Recall
   - Baseline：60% (基于关键词规则)
   - 目标：85% (生产要求)

5. **数据需求**
   - 最小：1000样本/类（共10000）
   - 理想：5000样本/类（共50000）
   - 计划：v1(10k) → v2(30k) → v3(50k)

## 总结

任务建模是数据构建的第一步，也是最关键的一步。它决定了：
- **做什么**：明确任务边界
- **怎么衡量**：定义成功标准
- **需要多少资源**：数据规模和成本

一个清晰的任务建模能节省后续80%的返工成本。
